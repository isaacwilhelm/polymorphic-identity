Base logic

About this site

This site maps what follows from what among principles of polymorphic identity: identity between items of different types, and identity between types. Pick some principles, and the site shows, for every other principle, whether it follows from them, is inconsistent with them, or is independent of them, together with the derivation or the model that shows it.

PI, the logic of polymorphic identity, is formulated in the predicative calculus of constructions. It has classical propositional logic, quantifiers over items of each type and over types, β-conversion, and the identity axioms Ref≡, Sym≡, Trans≡, LL≡, Ref≈ and LL≈. PI⁻ is PI without LL≡. PIᶜ is PI with Classicism added: whenever PI proves φ ↔ ψ, the propositions φ and ψ are identical, and so are the properties λx.φ and λx.ψ. In other words, logical equivalence suffices for identity. The axioms common to all three logics are listed in the window opened from the Explorer tab, and the identity axioms of the chosen logic are listed below the graph.

In a standard model, each type denotes a set, each function type denotes the set of all functions between the relevant sets, t denotes the two truth values, ≈ is an equivalence relation on types, and ≡ identifies some items of some types with items of others. Several of the models here use broader semantics, described below.

How the statuses are computed

Each result is entered as data: a derivation (given PI⁻, these principles prove that one), an inconsistency (given PI⁻, these principles prove ⊥), or a model (a model of PI⁻ in which certain principles are true and others false). For any selection, the site then reasons as follows.

  • Follows: the derivations, chained together (including by contraposition), yield the principle. The derivation is shown step by step.
  • Inconsistent: the derivations yield the principle's negation, or the principle together with the selection hits a known inconsistency.
  • Independent: some model makes every selected principle true and this one false, and some model makes them all true together. By soundness, it neither follows nor is refuted.
  • Consistent / Does not follow: only one of those two models is known.
  • Open: the recorded results do not settle it.

The chaining is sound but not complete: “open” means only that the recorded results, combined in this simple way, do not settle the question. Values inside a model that are not part of its construction, but follow from the recorded derivations, are filled in automatically.

What is checked in Lean

The folder lean/ contains a formalization of PI in the Lean proof assistant: the language, the proof system, the models, and a proof that the proof system is sound (whatever PI proves is true in every model). With soundness, a model in which a principle is false is a proof that PI does not prove it.

  • Models: every model on this site is checked to be a model of PI⁻ (and of PI where LL≡ is true in it), and every true/false value recorded for it is checked. Each principle's Lean definition links to the sentence as written in Lean.
  • Derivations: the derivations and inconsistencies are written out as formal derivations in PI (files lean/PIDerivations.lean, lean/PISchemas.lean, lean/PIModal.lean, lean/PIBarcan.lean and lean/PIClass.lean, among others). Each step of a “Follows” or “Inconsistent” explanation that rests on one of them carries a Lean ✓ badge.
  • A broader semantics: in standard models, the items of type t are the two truth values, and in every such model of PI, Int≈ and Ext≈ agree. The file lean/PITagged.lean repeats the semantics and the soundness proof for models in which propositions are more fine-grained than truth values (a truth value with a tag). One such model, 𝔐_int, shows that PI + Int≈ does not prove Ext≈.
  • A semantics with worlds: the file lean/PIWorlds.lean repeats the semantics and the soundness proof once more, for models in which propositions are sets of worlds, a sentence is true when it is true at the actual world, and identity may hold at some worlds and not others. These models separate the principles of necessity and grain (T, Collapse, NI≡, NI≈, ND≈, Booleanism, the Identity Identity, and the Barcan formulas for types).
  • The most general semantics with full function spaces: lean/PIAlg.lean repeats the soundness proof for models in which propositions form any set with a truth predicate, and each model supplies the operations for the connectives and quantifiers, subject only to their truth conditions; the standard, tagged, and world semantics are special cases. lean/PIAlgI.lean does the same for models in which, in addition, items of a function type are more fine-grained than their graphs (PI has neither η-conversion nor extensionality).
  • Soundness and completeness: for general models, a broader class of models in which function types need not contain every function, propositions need only have truth values, and types need not be freely generated. A formula is provable in PI⁻ together with any set of further sentences just in case it is true in every general model in which those sentences are true. Since PI is PI⁻ with LL≡ added, this covers PI too. Files lean/PIGeneral.lean (the definition, and soundness) and lean/PISyntax.lean, lean/PIEnum.lean, lean/PICompleteness.lean, lean/PICanonical.lean (completeness, by a Henkin construction); the final theorem is sound_complete.

For a few models (𝔐_κ, 𝔐_card, and 𝔐_ρ), the Lean model is a simpler construction than the one described, with the same pattern of true and false principles. Each model's Lean note says how it is built.
